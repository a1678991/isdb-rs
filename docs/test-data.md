# Test data and the gr-isdbt oracle

A fresh checkout passes `cargo test --workspace` with no external data:
every committed fixture is synthetic, generated by this project's own
encoders. Captures, recordings, IQ files and media are never committed
(the `.gitignore` excludes `*.ts`, `*.m2ts`, `*.cf32`, `*.cs8`, `*.cu8`,
`*.iq`, the usual media formats and a `media/` directory).

Some tests can additionally run on real data that you provide. They read
a path from an environment variable and print `SKIP` and pass when the
variable is unset or the file is missing. This page lists those variables,
how to make or capture suitable data yourself, and how to set up the
gr-isdbt differential test.

## Environment variables

| Variable | Points at | Enables |
|---|---|---|
| `ISDB_RS_CAPTURE_TS` | a terrestrial ISDB-T transport-stream capture (188/192/204-byte packets) | `isdb-ts` `tests/capture.rs` (every packet and section round-trips byte-identically, CRCs valid); `isdb-si` `tests/capture.rs` (every distinct SI section decodes typed and re-encodes byte-identically); `isdb-text` `capture_si_strings` (every NIT/SDT/EIT string decodes without issues and round-trips); `isdb-analyze` `tests/real_data.rs` (inspect decodes everything, validate, identity and mutation edits stay clean); `isdbt-mux` `tests/adts.rs` `capture_all_frames_conform` (every ADTS frame passes the B32 Part 2 header rules) |
| `ISDB_RS_OUR_TS` | a TS written by `isdb mux` (together with `ISDB_RS_CAPTURE_TS`) | `isdb-analyze` `ours_vs_capture` (prints a diff report of ours against the capture), `transplant_nit_between_captures_is_crc_and_cc_clean` |
| `ISDB_RS_RELAY_TS` | a recorded TS that you have the rights to relay, unscrambled (transport_scrambling_control '00') | `isdb-cli` `relay_recording` and `relay_recording_without_toml` (the recording through `ts-program` / `--relay`: video on 0x0111, no late PES, T-STD clean, `ts validate` without errors, ffmpeg decodes it, `loopback` passes; the decode check uses `ffmpeg` when installed) |
| `ISDB_RS_MEDIA_DIR` | a directory with `video.m2v` (MPEG-2 video ES) and `audio.m2a` (AAC ADTS) | `isdbt-mux` `tests/media.rs` `media_ffprobe` (10 s of `bench.toml` with your media; needs `ffprobe`), `tests/adts.rs` `media_audio_gate_follows_header_report`; `isdb-cli` `loopback_with_in_process_multiplexer` (media part), `media_aac_gate_matches_b32_part2_report` |
| `ISDB_RS_ORACLE_CONTAINER` | name of the running oracle container (default `isdb-oracle`) | `oracle/run_matrix.py` |
| `ISDB_RS_ORACLE_OUT` | output directory of the oracle matrix, inside the repository (default `target/oracle-matrix`) | `oracle/run_matrix.py` |

Run the opt-in tests with `--nocapture` to see their reports, for example:

```sh
ISDB_RS_CAPTURE_TS=/path/to/capture.ts cargo test --release -p isdb-ts --test capture -- --nocapture
ISDB_RS_CAPTURE_TS=/path/to/capture.ts cargo test --release -p isdb-si --test capture -- --nocapture
ISDB_RS_CAPTURE_TS=/path/to/capture.ts cargo test --release -p isdb-text --test synthetic capture -- --nocapture
ISDB_RS_CAPTURE_TS=/path/to/capture.ts ISDB_RS_OUR_TS=/path/to/ours.ts \
    cargo test --release -p isdb-analyze --test real_data -- --nocapture
ISDB_RS_MEDIA_DIR=/path/to/media cargo test --release -p isdbt-mux --test media --test adts -- --nocapture
ISDB_RS_RELAY_TS=/path/to/recording.ts cargo test --release -p isdb-cli --test cli relay_recording -- --nocapture
```

Statistics quoted in the crate READMEs, SPECS.md and SPEC-NOTES (for
example "144 distinct SI sections" or "217 EIT events without a short
event descriptor") are development results from a live terrestrial
capture, which is not distributed, so they cannot be reproduced from the
repository alone. The same opt-in tests print the corresponding figures
for your own capture.

## Making a media directory

The `ISDB_RS_MEDIA_DIR` tests take their expectations from the media files
themselves (picture size from the sequence header; sampling frequency,
channels, rate and B32 Part 2 rule violations from the ADTS headers), so
any MPEG-2 video elementary stream and any AAC ADTS file work. Audio with
violations, for example without crc_check, is expected to be refused by
the default `adts_compliance = "conform"` and accepted with `warn`;
conforming audio is expected to pass unchanged. FFmpeg makes a suitable
pair of test files:

```sh
mkdir -p media
ffmpeg -f lavfi -i testsrc2=size=1440x1080:rate=30000/1001 -t 10 -vf setfield=tff \
    -c:v mpeg2video -b:v 12M -maxrate 12M -bufsize 7M -g 15 -bf 2 \
    -flags +ilme+ildct -aspect 16:9 -f mpeg2video media/video.m2v
ffmpeg -f lavfi -i sine=frequency=1000:sample_rate=48000 -ac 2 -t 10 \
    -c:a aac -b:a 192k -f adts media/audio.m2a
ISDB_RS_MEDIA_DIR=$PWD/media cargo test --release -p isdbt-mux --test media --test adts
ISDB_RS_MEDIA_DIR=$PWD/media cargo test --release -p isdb-cli --test cli media
```

(Checked with FFmpeg 9.0: all media tests pass. FFmpeg's ADTS has no
crc_check, so the tests exercise the refusal path.)

## Capturing your own data

Receiving broadcasts is generally lawful, but what you may do with a
recording is not unlimited: in Japan private copying is permitted
(Copyright Act Art. 30), while redistributing broadcast content is not.
Keep captures, recordings and anything extracted from them (section
fixtures, IQ files) out of public repositories and issue reports; describe
what you see, or share small synthetic reproductions made with
`isdb mux` or `isdb ts edit` instead.

**Transport-stream capture.** Any tuner that delivers the whole TS works.
With a Linux DVB device (for example a MyGica S270), after a channel scan:

```sh
dvbv5-zap -c dvb_channel.conf -r -P -t 30 -o capture.ts "<channel name>"   # all PIDs, 30 s
```

**IQ capture with a HackRF** (receive only), then demodulate it:

```sh
hackrf_transfer -r capture.cs8 -f 557142857 -s 8126984 -l 16 -g 20 -n 81269840   # ch27, 10 s
isdb rx --iq capture.cs8 --iq-format cs8 --out capture.ts --json
```

The centre frequency of channel N is 473 + 6·(N − 13) + 1/7 MHz;
`-n` is the number of samples (8 126 984 per second). Mind the HackRF's
RX input limit (−5 dBm) when connecting anything other than an antenna.
Captures of other broadcasters, or from an antenna, remain the most useful
independent checks
([VERIFICATION.md](../VERIFICATION.md#open-questions)); a Pluto can capture
with `iio_readdev` or demodulate live with `isdb rx --radio pluto`.

**Scrambling.** In Japan the elementary streams of full-segment services
are scrambled; PSI/SI and the one-seg service are not. The SI-only tests
(`isdb-si`, `isdb-text`) only need the SI PIDs. Tests that parse PES
payloads (`isdb-ts` `capture`, `isdb-analyze` `real_data`, `isdbt-mux`
`capture_all_frames_conform`) need elementary streams that are not
scrambled (transport_scrambling_control '00'). This project does not
descramble and gives no help with it; circumventing broadcast protection
may be illegal where you are. Your own `isdb tx` output received with
`isdb rx`, or broadcasts that are transmitted unscrambled, are fine.

**Relay recordings** (`ISDB_RS_RELAY_TS`) must likewise be unscrambled
(transport_scrambling_control '00'); `isdb` refuses scrambled input. Use a
recording you have the rights to, for example a stream you produced
yourself. The relay keeps the source's copy-control signalling and its
CA_descriptor/ECM by default ([transmitting.md](transmitting.md)).

## The gr-isdbt oracle

`oracle/` holds the differential test against GNU Radio
[gr-isdbt](https://github.com/git-artes/gr-isdbt): the Rust transmitter's
output is decoded by gr-isdbt and gr-isdbt's output by the Rust receiver,
both compared packet by packet, and the two modulators' carriers are
compared directly. gr-isdbt is an external GPL-3.0 program; it is not
included here, and the scripts only call it at run time inside a
container. It is an oracle, not a reference: a disagreement is resolved by
reading ARIB STD-B31 ([VERIFICATION.md](../VERIFICATION.md)).

| File | Purpose |
|---|---|
| `grisdbt_tx.py` / `grisdbt_rx.py` | gr-isdbt transmitter / receiver flowgraphs (run inside the container) |
| `ts_compare.py` | anchors decoded packets on a unique source packet, then compares them in sequence |
| `iq_compare.py` | carrier-level comparison of two cf32 files, with DBPSK bit attribution for TMCC/AC |
| `run_matrix.py` | the whole matrix (8 parameter sets) |
| `rust_tx3/` | a stand-alone crate (not a workspace member): `rust_tx3` (a three-layer `tx_file`) and `rx_rot` (the carrier-rotation numbering check) |

**Licensing.** The scripts in `oracle/` are Apache-2.0. `grisdbt_tx.py`
and `grisdbt_rx.py` import GNU Radio and gr-isdbt (GPL-3.0) at run time,
so the combination that runs is under GPL-3.0; nothing of either is
distributed with this repository ([oracle/README.md](../oracle/README.md)).

**Container.** [`oracle/Dockerfile`](../oracle/Dockerfile) builds the
oracle environment: Ubuntu 24.04 with its GNU Radio 3.10 packages
(3.10.9.2) and gr-osmosdr, plus gr-isdbt built from
<https://github.com/git-artes/gr-isdbt> at the pinned commit
`56b2556c14ecc5d710070f969fda7a2deae65d8b` (the one the published results
were produced with; override with `--build-arg GR_ISDBT_COMMIT=…`). The
container must have this repository mounted at `/work`, because
`run_matrix.py` writes its inputs under the repository and runs the gr-isdbt
scripts through `docker exec`:

```sh
# from the repository root; the build takes a few minutes
docker build -t isdb-oracle oracle/
docker run -d --name isdb-oracle --user "$(id -u):$(id -g)" -v "$PWD":/work isdb-oracle
```

`--user` keeps the files the container writes owned by you. The container
just sleeps; `docker start isdb-oracle` restarts it later. To use another
name, pass it with `--name` and set `ISDB_RS_ORACLE_CONTAINER`.

**Run.** From the repository root:

```sh
cargo build --release -p isdbt-phy --examples
cargo build --release --manifest-path oracle/rust_tx3/Cargo.toml --target-dir target/oracle
python3 oracle/run_matrix.py               # all rows, about 2 minutes; or: python3 oracle/run_matrix.py m3g4p_bench
```

Results go to `target/oracle-matrix/<config>/` with a summary on stdout.
The per-step commands (gr-isdbt TX → Rust RX, Rust TX → gr-isdbt RX,
carrier comparison, rotation-numbering check) are in
[VERIFICATION.md](../VERIFICATION.md).
