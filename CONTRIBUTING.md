# Contributing to isdb-rs

Thank you for helping. This file covers the rules that are specific to this
project (specifications as ground truth, RF safety, test data) and the
mechanics (toolchain, hooks, checks, commits). The architecture and the
crate map are in [README.md](README.md).

## Ground rules

### The specifications are the only ground truth

- Behaviour is implemented from the published specifications listed in
  [SPECS.md](SPECS.md) (ITU-T H.222.0 | ISO/IEC 13818-1, ARIB STD-B10,
  STD-B21, STD-B24, STD-B31, STD-B32), in the editions given there.
- Other implementations (e.g. GNU Radio gr-isdbt, other TS libraries) are
  **not** references. Do not copy their code, tables or constants, and do not
  "fix" a disagreement by matching them. They may be run as independent
  oracles in differential tests (see [Oracle checks](#oracle-checks)); a
  disagreement is resolved by reading the spec.
- Every public item's doc comment names the clause or table it implements,
  e.g. `/// ARIB STD-B10 §5.2.6, Table 5-5`.
- Specification text is copyrighted and is **never committed**. Keep local
  extractions (`pdftotext -layout <pdf> specs/<name>.txt`) in the
  gitignored `specs/` directory. Short quotations in SPEC-NOTES entries are
  fine; whole tables or pages are not.

### Record every interpretation in SPEC-NOTES

When the spec text is ambiguous, garbled by PDF extraction or seemingly
inconsistent, add an entry to the `SPEC-NOTES.md` of the crate that
implements it (`crates/<crate>/SPEC-NOTES.md`; create it if the crate has
none and add it to the index in the top-level [SPEC-NOTES.md](SPEC-NOTES.md)).
Decisions that span crates go in the top-level file. Entry format:

```text
## <crate>: <topic>
- Spec: ARIB STD-B31 v2.2 §x.y, Table/Fig …
- Text: "…"
- Interpretation: …
- Confirmation: … (status: confirmed | pending real-world check)
```

Change an entry's status to `confirmed` only with evidence (a spec vector,
an oracle run, a real receiver or capture) and say which.

### Tests carry the proof

- Values printed in a spec (check values, tables, PRBS states, constellation
  points, frame lengths) are asserted directly; name such tests
  `spec_<table>_…`. Property tests are named `prop_…`.
- Decoders are lossless (reserved bits included): `encode(decode(x)) == x`
  is property-tested. Decoders return errors on malformed input; they do
  not panic.
- Each TX stage has its RX inverse tested as an identity.
- Committed fixtures are synthetic, generated by this project's own
  encoders.

### RF safety (hardware contributors)

Radiating on broadcast (UHF TV) frequencies requires a licence: in Japan
under the Radio Act (電波法), elsewhere under local law. Contributors who
run the transmit path on hardware must:

1. Use a **conducted or shielded** setup only: coax with attenuators straight
   into the receiver, or a shielded enclosure. No antenna on the TX port.
2. Check the settings first without radiating: `arib tx --hackrf … --dry-run`
   (or without `--rf-enable`), which prints the RF settings and exits.
3. Add `--rf-enable` only on that bench; start with low TX VGA and leave the
   RF amplifier off (`--amp` is opt-in). Bound runs with `--seconds` where
   practical.
4. Only transmit or relay content you have the rights to. The project does
   not descramble and refuses scrambled input; changes that add
   descrambling or conditional-access (B-CAS) support will not be accepted.

Rules for code changes:

- Nothing may radiate without the explicit `--rf-enable` flag; keep every
  exit path stopping the stream and switching the amplifier off.
- Tests, examples run by tests, and CI never open a radio device. Hardware
  checks are manual and are described in the PR (setup, attenuation,
  channel, gains).

### Real capture data never enters the repository

Captures, recordings, media and IQ files are never committed (`*.ts`,
`*.m2ts`, `*.cf32`, `*.cs8`, `*.cu8`, `*.iq` are gitignored). Tests that need
them read a path from an environment variable and print `SKIP` and pass when
it is unset or the file is missing, so a fresh checkout passes with no data:

| Variable | Points at |
|---|---|
| `ISDB_RS_CAPTURE_TS` | an unscrambled terrestrial ISDB-T capture (188-byte TS) |
| `ISDB_RS_OUR_TS` | a TS produced by `arib mux`, compared with the capture |
| `ISDB_RS_RELAY_TS` | an unscrambled recording you may relay (`ts-program`) |
| `ISDB_RS_MEDIA_DIR` | bench media: `v63p.m2v` (MPEG-2 video), `a.m2a` (ADTS AAC); some tests also need `ffprobe` |

Which tests read which variable is documented in each crate's README. New
real-data tests must follow the same pattern (`ISDB_RS_` prefix, skip when
unset, never fail for missing data).

## Development setup

- **Rust**: install [rustup](https://rustup.rs/); `rust-toolchain.toml`
  selects the pinned toolchain (with rustfmt and clippy) automatically. The
  minimum supported Rust version is `rust-version` in `Cargo.toml` (1.88);
  `make msrv` needs it installed: `rustup toolchain install 1.88 --profile minimal`.
- **libhackrf**: `crates/hackrf` links the system library even when no radio
  is attached (Arch `hackrf`, Debian/Ubuntu `libhackrf-dev`, Homebrew
  `hackrf`).
- **Harness tools** (recommended): install [mise](https://mise.jdx.dev/),
  then run `mise install` in the repository. It installs the pinned
  node/pnpm (commitlint), lefthook, cargo-deny, actionlint, zizmor, pinact and
  shellcheck, runs `pnpm install` and installs the git hooks
  (`lefthook install`).
- Without mise: `cargo install --locked cargo-deny` is enough for every
  `make` target; the git hooks then need lefthook and pnpm installed by hand.

### Git hooks

Managed by lefthook (`lefthook.yaml`, installed into `.git/hooks` by
`mise install` or `lefthook install`):

| Hook | Runs |
|---|---|
| `pre-commit` | `make fmt` on staged `*.rs` (re-staged), `make clippy` when Rust files or manifests change, `make deny-offline` when manifests or `deny.toml` change, actionlint / zizmor / pinact on workflow changes, `mise lock` on `mise.toml` changes |
| `commit-msg` | commitlint (Conventional Commits) |
| `pre-push` | refuses direct pushes to `main` |

Skip once with `LEFTHOOK=0 git commit …` (CI runs the same checks anyway).

### Checks

The Makefile is the single entry point; CI runs the same targets.

| Command | What it does |
|---|---|
| `make check` | everything CI runs (below) |
| `make lint` | `fmt-check` + `clippy` |
| `make fmt` / `make fmt-check` | rustfmt (workspace and `oracle/rust_tx3`) |
| `make clippy` | clippy on all targets, `-D warnings` |
| `make test` | unit, integration and doc tests (ignored tests excluded) |
| `make test-release` | the same in release (faster PHY loopbacks) |
| `make test-ignored` | heavy stress/throughput tests, release (not in CI) |
| `make doc` | rustdoc with `-D warnings` |
| `make deny` | cargo-deny: advisories, bans, licences, sources |
| `make msrv` | `cargo +<rust-version> check` on every target |
| `make oracle` | clippy on the stand-alone `oracle/rust_tx3` helper |

Lints are configured once in `[workspace.lints]` (`Cargo.toml`); every crate
opts in with `[lints] workspace = true`. `unsafe_code` is denied everywhere
except the FFI crate `hackrf`, which allows it in `src/lib.rs`. Do not add
`#[allow(...)]` to silence a lint without a comment that says why.

New dependencies must pass `make deny` (crates.io only, licences compatible
with Apache-2.0) and build with the MSRV. Raising the MSRV is a deliberate
change: say so in the PR and in the changelog.

### Oracle checks

`oracle/` holds the differential test against GNU Radio gr-isdbt, an
external GPL-3.0 program that is **not** distributed here and must not be
vendored or copied. Run it when you change `isdbt-fec`, `isdbt-ofdm` or
`isdbt-phy` behaviour:

```sh
cargo build --release -p isdbt-phy --examples
cargo build --release --manifest-path oracle/rust_tx3/Cargo.toml --target-dir target/oracle
python3 oracle/run_matrix.py        # rows 1-8, about 2 minutes
```

The scripts expect a container with GNU Radio 3.10 and gr-isdbt that has the
repository mounted at `/work` (name `arib-sdr`, override with
`ISDB_RS_ORACLE_CONTAINER`); results go to `target/oracle-matrix/`
(`ISDB_RS_ORACLE_OUT`, which must lie inside the repository). Full
reproduction steps and the current results are in
[VERIFICATION.md](VERIFICATION.md). A disagreement with the oracle is an
investigation, not a bug report against either side: settle it with the
spec and record the outcome in SPEC-NOTES / VERIFICATION.md.

## Commits and pull requests

- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `perf:`, `chore:`,
  `ci:` …). The optional scope is a crate directory name (`arib-ts`,
  `isdbt-ofdm`, …) or `oracle`, `workspace`, `ci`, `deps`. commitlint
  enforces this in the hook and in CI.
- Work on a branch and open a pull request; `main` is merged by squash.
  CI (`CI` and `Lint` workflows) must be green.
- Add a line under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md) for
  user-visible changes.
- Update the crate README and SPEC-NOTES in the same PR as the behaviour
  they describe.

## Reporting security issues

Do not open public issues for vulnerabilities; see [SECURITY.md](SECURITY.md).
